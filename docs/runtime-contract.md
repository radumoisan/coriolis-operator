The future `core` profile targets exact official release `2603.4` and deploys Kubernetes workloads, not an external VM. ## :material-book-open-page-variant-outline: Network And Ingress Policy

Community ingress-nginx is the short-term controller. The operator locally owns three `networking.k8s.io/v1` Ingresses only and will not install the controller or create, mutate, or delete certificate Secret material. `certManager` derives `<host>-tls` and only the primary web Ingress annotates a ready defaulted or explicit `ClusterIssuer`; `existingSecret` alone accepts a same-namespace external `tlsSecretName` and no Ingress emits an issuer annotation. Defaults are host `coriolis.app.cloudbase.wiki`, class `nginx`, issuer `letsencrypt`, and derived `<host>-tls` Secret.

Ingress is the only external exposure. Backend and dependency Services are ClusterIP and plaintext, which assumes a trusted cluster network and is not encryption. Ingress terminates TLS and redirects HTTPS, then uses HTTP backends. The local implementation creates web `/` (`Prefix`) to TCP `3000` without rewrite, Keystone `/identity(/|$)(.*)` to TCP `5000` with `/v3/$2`, and API `/coriolis(/|$)(.*)` to TCP `7667` with `/v1/$2`. They share resolved host/class/TLS and exact-origin `https://<host>` CORS, permitting `POST`, `GET`, `OPTIONS`, `DELETE`, `PUT`, and `PATCH`, preserving `X-Auth-Token`/`X-Subject-Token`, and exposing `X-Subject-Token`. No dedicated backend route targets `/log-stream`, Barbican, logger, licensing, or Metal Hub while their Services are absent; unmatched paths use the web `/` `Prefix`/SPA fallback until a more-precedent route is implemented. A future dedicated `/log-stream` logger route requires WebSocket support.
