# 0006: Use Ingress-NGINX for Kubernetes Runtime Exposure

## :material-book-open-page-variant-outline: Context

The appliance needs one public HTTPS origin while its Coriolis API, web UI, and future dependency backends communicate on the cluster network. The former appliance design included an initial web proxy and Step CA bootstrap, but neither is part of the initial Kubernetes runtime.

## :material-book-open-page-variant-outline: Decision

Use the community ingress-nginx controller for short-term public exposure. The local operator implementation owns three appliance `networking.k8s.io/v1` Ingress resources, but will never install the controller or create, mutate, or delete TLS certificate Secret material.

The per-CR ingress contract supports `certManager` and `existingSecret` modes. `certManager` always derives `<host>-tls`; only the primary web Ingress annotates a ready defaulted or explicit `ClusterIssuer`. `existingSecret` alone accepts an externally managed same-namespace `tlsSecretName` and no Ingress emits an issuer annotation. TLS terminates and redirects at Ingress; every backend and dependency Service is ClusterIP and plaintext. The logical public origin is exactly `https://<host>`.

## :material-book-open-page-variant-outline: Consequences

ClusterIP is not encryption. Plaintext backend traffic is accepted only within a trusted cluster network; clusters needing encryption or stronger workload isolation require a separate approved design. Local source creates owner-referenced `<appliance>-coriolis-web`, `<appliance>-keystone`, and `<appliance>-coriolis-api` Ingresses after API and web Service/Deployment, in that order, before the marker. Web routes `/` (`Prefix`) to TCP `3000` without rewrite; Keystone routes `/identity(/|$)(.*)` to TCP `5000` with `/v3/$2`; API routes `/coriolis(/|$)(.*)` to TCP `7667` with `/v1/$2`. They share resolved host/class/TLS, HTTPS redirect, and exact-origin CORS with source-evidenced methods and token headers; no wildcard is emitted. No dedicated backend route targets an absent Service; unmatched paths use the web `/` `Prefix`/SPA fallback until a more-precedent route exists. A future dedicated `/log-stream` logger route requires WebSocket support. All three pre-reads/classifications/preflight complete before mutation; collisions are mutation-free and all-or-nothing; managed repair is resourceVersion-guarded SSA; failures are sanitized and skip later writes/marker. Ingress RBAC is only `get`/`create`/`patch`; `spec.ingress` changes reconcile. Host uniqueness across CRs is an external deployment precondition and is not enforced with list-free RBAC; multi-CR route/certificate conflicts remain unvalidated.
